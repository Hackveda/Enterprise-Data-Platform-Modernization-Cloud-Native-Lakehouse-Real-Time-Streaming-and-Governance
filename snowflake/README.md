# Snowflake Integration

This optional path keeps the existing local DuckDB demo intact and adds a production-style Snowflake warehouse path:

PostgreSQL -> local raw Parquet -> Snowflake RAW -> dbt STAGING -> dbt MARTS

The real-time Kafka/MinIO simulator remains unchanged.

## 1. Create a Snowflake account

Create or use an existing Snowflake account and note the account identifier shown in your Snowflake connection details. The Python connector expects the account identifier, not the browser URL.

## 2. Bootstrap database, schemas, role and warehouse

Open a Snowflake worksheet as ACCOUNTADMIN and run `snowflake/setup.sql`.

Before running the CREATE USER statement, replace `CHANGE_ME_IMMEDIATELY` with a temporary strong password. The script creates:

- warehouse: `PLATFORM_WH`
- database: `ENTERPRISE_PLATFORM`
- schemas: `RAW`, `STAGING`, `MARTS`
- role: `PLATFORM_ROLE`
- demo service user: `PLATFORM_APP`
- raw tables: `RAW_CUSTOMERS`, `RAW_ORDERS`, `RAW_ORDER_EVENTS`

For a production deployment prefer key-pair/OAuth authentication and a secret manager rather than a password in shell history.

## 3. Configure EC2 environment

Never commit Snowflake secrets to Git. On EC2 export them for the current session:

```bash
export SNOWFLAKE_ACCOUNT='your_account_identifier'
export SNOWFLAKE_USER='PLATFORM_APP'
export SNOWFLAKE_PASSWORD='your_password'
export SNOWFLAKE_ROLE='PLATFORM_ROLE'
export SNOWFLAKE_WAREHOUSE='PLATFORM_WH'
export SNOWFLAKE_DATABASE='ENTERPRISE_PLATFORM'
```

## 4. Install Snowflake dependencies

```bash
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## 5. Start local source infrastructure

```bash
docker compose up -d postgres redpanda minio
docker compose ps
```

## 6. Run the complete Snowflake pipeline

```bash
chmod +x scripts/run_snowflake_demo.sh
./scripts/run_snowflake_demo.sh
```

Or:

```bash
make snowflake
```

The runner performs:

1. PostgreSQL extraction to `data/raw_batch/*.parquet`
2. load to `ENTERPRISE_PLATFORM.RAW`
3. `dbt debug`
4. dbt staging and mart builds
5. dbt data-quality tests
6. Snowflake row-count and KPI verification

## 7. Run each layer manually

```bash
python batch/extract_postgres.py
python scripts/load_snowflake.py

dbt debug --project-dir warehouse/dbt_snowflake --profiles-dir warehouse/dbt_snowflake
dbt run --project-dir warehouse/dbt_snowflake --profiles-dir warehouse/dbt_snowflake
dbt test --project-dir warehouse/dbt_snowflake --profiles-dir warehouse/dbt_snowflake

python scripts/verify_snowflake.py
```

## 8. Verify directly in Snowflake

```sql
USE ROLE PLATFORM_ROLE;
USE WAREHOUSE PLATFORM_WH;
USE DATABASE ENTERPRISE_PLATFORM;

SELECT COUNT(*) FROM RAW.RAW_CUSTOMERS;
SELECT COUNT(*) FROM RAW.RAW_ORDERS;

SELECT COUNT(*) FROM STAGING.STG_CUSTOMERS;
SELECT COUNT(*) FROM STAGING.STG_ORDERS;

SELECT COUNT(*) FROM MARTS.MART_ORDERS;

SELECT
  COUNT(*) AS order_count,
  ROUND(SUM(amount), 2) AS gmv,
  COUNT(DISTINCT customer_id) AS customers,
  MAX(updated_at) AS freshest_record
FROM MARTS.MART_ORDERS;
```

## Layer meanings

- `RAW`: minimally transformed source copies used for traceability and replay.
- `STAGING`: cleaned names/types/standardized values generated by dbt.
- `MARTS`: business-ready joined tables for APIs, BI and analytics.

## Cost control

`PLATFORM_WH` is X-Small and auto-suspends after 60 seconds. Do not leave worksheets or workloads continuously querying it during a demo.
